# Cicada Operations

Внутреннее рабочее пространство проекта Cicada Payments. Сайт объединяет описание будущего продукта, последовательность разработки, глобальную схему платформы, конкурентный анализ, выводы исследования и открытые вопросы.

## Структура сайта

- `/` — главная страница и карта рабочего пространства.
- `/projects.html` — Project description: Cicada Core и три прикладных продукта.
- `/roadmap/` — этапы и логика развития платформы.
- `/scheme.html` — Global Scheme: участники, продукты, Core, внешняя инфраструктура и сквозной путь платежа.
- `/competitors/` — рынок, shortlist и карточки конкурентов.
- `/conclusions/` — выводы конкурентного анализа, целевые принципы и дальнейшие исследования.
- `/open-decisions/` — открытые вопросы, которые необходимо закрыть до фиксации MVP.
- `/404.html` — базовая страница для удалённых и несуществующих адресов.

Все публикуемые файлы находятся в каталоге `public`. Общие стили собраны в `public/styles.css`; интерактивные страницы используют собственные JavaScript-файлы рядом с HTML.

## Русская и английская версии

На всех восьми страницах, включая 404, в шапке доступен переключатель **Ru / En**. Русский — исходный язык; выбор сохраняется в браузере. Параметры `?lang=ru` и `?lang=en` явно задают язык ссылки и имеют приоритет над сохранённым выбором. Другие параметры и якоря сохраняются. Переключение не перезагружает страницу и не сбрасывает раскрытые карточки или вкладки.

- `public/i18n.js` — общий механизм переключения, локализация метаданных, подписей доступности и динамически созданных элементов.
- `public/locales/en.js` — проверенный английский словарь. Ключи — исходные русские тексты с пробелами, приведёнными к одному, и без пробелов по краям. При изменении русского текста обновляйте соответствующий ключ и перевод; одинаковый текст на разных страницах использует общий перевод.
- Исходные HTML и данные страниц остаются русскими. Без JavaScript или при недоступности словаря сайт сохраняет русское содержимое.
- Языковые ссылки остаются относительными и работают как в корне домена, так и в каталоге GitHub Pages. Внешние ссылки и ссылки на файлы не изменяются.

Проверка перевода и переключения: при доступном пакете Playwright запустите `node scripts/check-i18n.cjs` после запуска локального сервера. При необходимости задайте `SITE_URL` и `CHROME_PATH`; проверка не изменяет содержимое сайта.

## Локальный просмотр

```bash
python3 -m http.server 8080 --directory public
```

После запуска сайт доступен по адресу `http://127.0.0.1:8080/`.

## Публикация

Workflow `.github/workflows/deploy-pages.yml` публикует каталог `public` в GitHub Pages после push в ветку `main`.

Для Timeweb App Platform используется приложение типа `Frontend → HTML/CSS/JS`, ветка `main` и каталог публикации `/public`. Чтобы отсутствующие файлы получали корректный HTTP-статус `404`, в `Настройки → Настройки веб-сервера` нужно выключить `SPA Fallback`. После этого платформа будет отдавать созданный файл `404.html`, а не подменять неизвестные маршруты главной страницей.
